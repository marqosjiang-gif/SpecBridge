# SpecBridge 需求翻译官

把业务语言翻译成可开发、可验收的产品规格：需求拷问、用户故事拆解、优先级排序、界面推理与里程碑定义，产出 Spec 文档。

## 类型

Agent 型（单个 AI 专家）

## 功能

SpecBridge 专精 vibe-coding 交付流程的前半段——需求深度拷问 → 规格冻结 → 技术设计 → Issue 拆解：

1. 需求深度拷问：先冻结问题、范围、非目标和验收标准，再谈方案
2. 用户角色收敛：AI 提候选角色，人拍板收敛（宁少勿多）
3. 用户故事梳理：稳定编号、"作为谁我希望…从而达到…"句式、主次分明
4. 优先级排序：P0/P1/P2，AI 给建议+理由，人拍板
5. 故事→功能→界面推理：每个功能可追溯到用户故事
6. 数据模型与技术栈建议：字段级表结构 + 多方案权衡
7. 里程碑拆解：M1/M2 五要素（目标/范围/前置/交付/完成条件），产出含"规格/合格标准/证据"三件套的 READY Issue

内置**五份全流程提示词模板**（项目建设 / 用户故事与优先级 / 产品功能与页面结构 / 技术方案 / 开发里程碑）+ vibe-coding 交付治理门禁，全文见 `skills/spec-bridge/references/`。

## 使用示例

- 帮我把这个想法翻译成可冻结、可验收的产品规格
- 按用户故事梳理这个产品的功能优先级
- 把这个产品拆成可独立验收的开发里程碑
